# Whisper fallback transcription (data_retrieval.md §4.2/4.3) for videos
# whose auto-captions are missing or fail the quality heuristic. Pulls in
# torch -- doesn't pin a version itself, so pip resolves latest by default.
#
# torch PINNED to 1.13.1 (found 2026-08-22): the school/lab Windows Server
# machine's CPU/VM does not expose AVX2 (confirmed via
# IsProcessorFeaturePresent(40) == false). torch >=~2.0's default CPU
# kernels hard-require AVX2 with no fallback and crash during DLL init --
# on Windows this surfaces as generic `[WinError 1114] c10.dll` with NO
# missing dependency (confirmed clean via Dependencies.exe -chain), which
# is what made this look like the DLL/TLS race chased earlier today. It
# wasn't -- that fix (preload_whisper() before worker threads exist) is
# still correct/needed for its own reason, but the *dominant* failure mode
# on this machine was AVX2, not TLS. torch==1.13.1 uses MKL with an SSE
# fallback and imports/computes cleanly on this hardware. Verified 26/26
# (0 failures) on a real --workers 8 batch spanning 3 categories after
# this pin -- the same concurrency load that previously failed 15-35% of
# videos. If moving to a machine with AVX2 (e.g. the A40 server, if it
# has AVX2 -- untested), a newer torch + numpy>=2 pin can likely be
# restored; re-verify before assuming.
torch==1.13.1
openai-whisper==20250625
